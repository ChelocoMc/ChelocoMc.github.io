Mantenimiento de base de datos SQL Server

Los procesos nocturnos corrían «bien»: terminaban sin avisar de nada y entregaban cifras equivocadas a la jefatura. El trabajo fue encontrar dónde mentía la lógica, corregirla y dejar los jobs con guardas para que un fallo se note el mismo día.

Los tres jobs quedaron con guardas para poder re-ejecutarlos sin duplicar datos. 

    

  


  
Los tres errores que producían cifras equivocadas


  

    
1 · Dos situaciones distintas contadas como una

    

      
Antes
CASE
  WHEN prev.id IS NULL THEN 'Sin gestion'
  ELSE 'Gestionado'
END AS categoria

      
Después
CASE
  WHEN prev.id IS NULL      THEN 'Sin prevision asignada'
  WHEN ot.id   IS NULL      THEN 'Con prevision, sin OT'
  ELSE 'Gestionado'
END AS categoria

    

    
Un equipo sin previsión asignada y un equipo con previsión pero sin orden de trabajo
       son problemas distintos, con responsables distintos. Agrupados en una sola categoría, el informe
       mostraba un número que no permitía actuar. Separarlos cambió las cifras que veía la jefatura.

  


  

    
2 · Conteo sobre la columna equivocada

    

      
Antes
SELECT anio,
       COUNT(estado) AS total
FROM  resumen_anual
GROUP BY anio;

      
Después
SELECT anio,
       COUNT(DISTINCT aviso_id) AS total
FROM  resumen_anual
GROUP BY anio;

    

    
Contar por una columna repetida infla el total anual. El síntoma era una cifra que
       nadie podía cuadrar contra el sistema origen; la causa, un COUNT apuntando a la
       columna que no identifica el registro.

  


  

    
3 · Un job que fallaba todas las noches en silencio

    
-- El job de índices requiere estas opciones de sesión; sin ellas
-- falla al tocar cualquier índice sobre columna calculada.
SET QUOTED_IDENTIFIER ON;
SET ANSI_NULLS ON;

-- Guarda: no reconstruir si otro proceso dejó la tabla bloqueada
IF NOT EXISTS (SELECT 1 FROM sys.dm_tran_locks WHERE resource_type = 'OBJECT'
               AND request_mode = 'X' AND resource_associated_entity_id = OBJECT_ID('dbo.avisos'))
BEGIN
    ALTER INDEX ALL ON dbo.avisos REBUILD WITH (ONLINE = ON);
END

    
Llevaba meses fallando por una configuración de sesión. Se corrigió y se agregaron
       guardas para que re-ejecutarlo sea seguro, porque un job que no se puede repetir sin miedo
       termina no ejecutándose nunca.
